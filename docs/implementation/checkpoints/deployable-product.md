# Deployable product checkpoint

Date: 25 August 2026
Status: ready for user visual review

## What is complete

- A citizen can enter the fictional session, file with route assistance, override the suggestion, or finish with assistance disabled.
- Review corrections, acknowledgement, timeline, Resolution Receipt and focused appeal are functional and deterministic.
- The primary journey is reviewed in English and Hindi; all 23 language choices remain visible with honest provenance for preview catalogues.
- Help, privacy, service scope, excluded-subject handoffs, prototype limitations and the no-government-fee warning are available on the product route.
- Runtime readiness is informative and recoverable without making the judge journey depend on a waking free database.
- The product includes responsive behavior, keyboard-visible controls, production metadata, security headers, a health check, standalone output, a container definition and CI validation.

## Original-service parity decision

The prototype does not claim CPGRAMS lacks voice, multilingual lodging, registration-based status or appeal. Those capabilities already exist. The judged improvement is accountable continuity: the citizen's requested outcomes, evidence gaps and disputed outcome remain connected across filing, resolution and appeal.

See [the live parity audit](../original-parity-audit.md) for the complete comparison.

## Automated evidence

- ESLint and strict TypeScript pass.
- Seven unit/component tests pass.
- Four judge journeys plus the component and runtime checks pass in each of the compact and wide browser projects (fourteen Playwright tests in total).
- The appeal path has no serious or critical automated axe findings.
- The production build completes with standalone server output.

## Intentionally deferred

- official identity, OTP/CAPTCHA, public officer and admin workflows;
- live CPGRAMS routing, notification, voice, upload and government-system integration;
- production retention, procurement, audit certification and authorised government cloud setup;
- durable authentication/case writes, which are represented by the real reviewed schema but mocked for the judge experience.

## User checkpoint

Review the finished citizen product and provide one consolidated UI-change list. After that iteration, configure the free public host, run the deployed smoke test and assemble the submission package.
